# Native RTVE audio, programme inventories and verification proxy

Version 0.204.0 adds the native rtveaudio provider, with first subset evidence for frozen keys rtve.es:audio and rtve.es:program. It supports canonical public RTVE/RNE audio pages, short audio/share/API IDs, legacy audio aliases and modern/legacy radio programme pages or numeric programme/share IDs. Complete RTVE video, live and television keys remain unimplemented. No generic embedded video is substituted for a selected RTVE resource.

The implementation reads current first-party api.rtve.es page envelopes. Single audio binds the requested numeric ID to the API row, canonical page, recorded audio type, publication state, duration and full MP3 qualities. Every offered quality has a unique issuer identifier, concrete approved HTTPS MP3 resource, complete byte count and matching duration. Placeholder provider/token URLs, unknown codecs, foreign origins, identity/type/duration/size changes and incomplete envelopes fail explicitly. Native full-size/decoder/duration verification remains in force. DRM, paid access, unpublished/disabled/non-downloadable media and ungranted regions never become successful playback. Returned URLs are used as declared; guest tokens are not invented.

Programme slugs are bound through the page's unique DC.identifier and confirmed canonical programme API identity. Inventories use the observed size/page parameters and validate page number, offset, size, item count, total, total pages and the configured complete-inventory limit. A changing, repeated or incomplete page fails without a partial-success list. Original positions, repeated occurrences and unavailable members are preserved. Programme-level access restrictions apply to all entries. The selected programme API is the membership authority: public aggregate programmes can legitimately contain episodes credited to another programme. Each member still binds its own exact audio ID, canonical page and archive identity. Inventory entries retain no signed playback resources. Selected audio is re-read through its own current API response; saved inspections revalidate parent membership, refusing a replaced selection before media transfer or publication.

The provider uses the existing bounded playback renewal and native publication/archive/recovery machinery. Current guest audio redirects are confined to ztnr.rtve.es and the observed rtve-mediavod-lote3.rtve.es delivery origin. API metadata/rights are refreshed once after a rejected media grant; actual media denial is preserved. Changing verification connections cannot reuse another cached grant. Native and explicitly selected curl file transports both preserve normal media routing. Analysis, no-overwrite, archive repeats, cancellation/process ownership, retained originals, metadata processing and FLAC conversion retain their existing native contracts.

Network.GeoVerificationProxy is now provider-scoped, rather than globally refused. RTVE declares its public metadata/rights API route. The connection accepts an HTTP/HTTPS proxy server without embedded credentials, extra paths, queries or fragments. Only the RTVE API verification session uses this proxy. Source cookies, custom headers, referrer, resource queries and playback authorization are excluded; API redirects are refused. Ordinary media retains Network.Proxy and its native redirect/renewal rules. The new typed --geo-verification-proxy option reaches both download and read-only analysis. WPF saved/job precedence, immutable capture, invalid-value redaction and unsupported-provider refusal are verified. The operational configuration is absent from request metadata, publication recipes and diagnostic record text. Country/IP overrides, authenticated proxies and verification routes for other providers remain unsupported.

Validation on the frozen candidate: Release has zero warnings/errors; 3,047 complete native core checks, seven affected media checks, 178 app checks and 65 focused checks pass. Fifty-one new core checks cover audio/collection identities, all-page order, duplicate/unavailable/aggregate members, item/programme refusals, malformed resources/paging, protected jobs, typed/redacted settings, real HTTPS verification/media proxy separation, native/curl token renewal, retained media denials and strict certificate isolation. Six new app checks cover saved, overridden, analysis, immutable, invalid and unsupported-provider settings. Seven media checks include five retained successful workflows, an opaque-curl refusal and a stale-inspection refusal. The full optional HDR/live suite was not rerun; its prior complete 0.200.0 checkpoint remains recorded.

Five generated workflows verify full MP3 transfer, metadata editing, FLAC conversion, inspected selected-member playback and interrupted processing/publication recovery. Two actual public downloads of RTVE audio 6978235 complete through native and curl, with metadata, exact retained originals and no new callbacks on archive repeat. Native/curl original bytes match. Complete inspection of the public Ficción sonora programme returns 179 entries; an independent four-page API read verifies every ID and position in order. Independent verification decodes 16 generated/public source/output files, including embedded public cover pictures, and verifies 17 comparisons, 22,422 exact coded audio packets and 50,921,856 exact PCM24 samples. No real account is accessed or verified.

Evidence is retained in work/broadcast-provider-batch, work/broadcast-provider-probe and work/broadcast-provider-public in the Codex continuation workspace, including reference captures, independent-{summary,decodes,comparisons,inventory}.json, compatibility-0.202.json, test logs/exits and preservation.json. Default policy/request JSON, publication recipes and track recovery identities match the verified 0.202.0 binary. The initial public aggregate-programme ownership assumption was corrected against the live contract before final regression/proof runs.

Five classic settings remain globally refused: Network.GeoBypassCountry, Network.GeoBypassIpBlock and the three Auth.Ap* fields. Geo verification proxy support remains limited to the declared RTVE contract. Adobe's current registration flow requires a registered application/software statement before its protected authentication APIs can be integrated; no unimplemented login setting is accepted and no account verification was attempted. Zing's public home request returned restrict.html in this environment, so no Zing playback or coverage is claimed. Continue those contracts and missing provider families alongside RTVE video/live/caption/encoding and account routes. Preserve the frozen 1,731-key/126-setting/276-option scope, all prior work and the still-blocked original packaging/native cutover acceptance.

## Implemented scope

- Completed fragment receipts record SHA-256, byte length, an exact strong entity tag when supplied, and the full entity length. URLs, signed query strings, cookies and account credentials are not serialized.
- Each retry compares the current complete track/timeline facts and provider-bound identity. Reused network fragments require a fresh conditional range request through the current authorization session, an unchanged strong tag and matching range/entity lengths. A changed entity is downloaded again. Missing or weak validators cause fresh transfer; a denied request cannot use cached bytes.
- Local fragments are hashed while held against writes, then copied into new ordered assembly. Corruption, truncation or malformed receipts cannot publish stale content. New receipt files are flushed and installed atomically; checkpoint ownership and exclusive process locks protect simultaneous retries. Linked or unrelated files are not traversed or deleted.
- Static HLS supports initialization, AES-128 with fresh job-owned keys, byte ranges, discontinuity/timing facts and ordered concurrent recovery. DASH template/list/JSON tracks share this mechanism. Indexed DASH reloads its segment index, binds the current index and representation facts, then reuses validated media ranges without changing file offsets.
- Inline Vimeo initialization is reusable only when fresh issuer metadata supplies the same bytes. The selected clear track's original coded data remains intact.
- Native collection snapshots revalidate membership before playback. Removed/unavailable members and changed hosted identities stop before cached transfer. Restart mode fetches fresh data. Recovery state survives caption/processing failure and is removed after successful publication.

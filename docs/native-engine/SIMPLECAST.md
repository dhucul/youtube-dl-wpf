# Native Simplecast verification

The independent C# provider in native engine 0.89 supports current public Simplecast episodes, hosted websites, episode/show players and complete published podcast inventories. It uses no Python, yt-dlp runtime, extractor import or fallback. Coverage of the frozen `simplecast`, `simplecast:episode` and `simplecast:podcast` keys remains partial. Production WPF cutover remains pending the full replacement's verification.

## Public protocol and scope

Supported addresses include UUID episode players, `show=true` podcast players, direct public episode/podcast API addresses, and Simplecast hosted website roots and `/episodes/SLUG` pages. HTTP addresses normalize to HTTPS. Player display options and supported color fragments do not change the requested media identity. Private-token, manually paged, filtered, ambiguous and unsupported routes fail explicitly.

Current publisher player and website JavaScript were inspected as protocol evidence without executing them. Hosted websites use the publisher's anonymous, read-only POST searches for an exact site URL and episode URL. Returned website, podcast and episode slug/UUID identities must agree. Direct UUID lookup and selected children use anonymous GET metadata. This implementation does not call publishing, editing, analytics-writing or authentication endpoints, or retain metadata tokens in its public output.

Episode and podcast hrefs must bind the requested UUID. The podcast must be explicitly public and published; the episode must be published, visible and transcoded. The exact supplied MP3 link must agree with its audio-file record and bind both podcast and episode IDs on a supported Simplecast audio origin. Informational byte estimates are not exact transfer-size claims. Full local MP3 decoding and media roles are checked before publication. Fixed Simplecast CDN media uses the declared-duration equality check. Supplied SXM dynamic-audio links instead require at least the declared program duration, allowing added audio without accepting short sources. Existing complete-transfer and decoding checks remain in place. Playback is anonymous, with native original retention, metadata/artwork, conversion and stable episode archives.

Podcast lists use published-only, public, latest-first pages of 100 entries. Listing ownership, counts, page numbering and bounded next links are checked. Each continuation retains the podcast, limit, offset, private flag, sorting and status. Missing terminal state, early termination, repeated episodes, count changes, wrong owners and configured limits fail without truncation. Unavailable slots retain source numbering. Inspected selections preserve original identities/positions and refresh only chosen episodes. Archived UUID children skip playback discovery.

The [official embedding guide](https://help.simplecast.com/hc/en-us/articles/21960653698973-How-to-Embed-Your-Podcast-and-Episodes) describes episode and dynamic show players. Current public player/website scripts and API responses were inspected on October 9, 2026; the [official API portal](https://apidocs.simplecast.com/) is also linked for reference. These are public observations, not a guarantee about undocumented future response layouts.

## Verification

Twelve core checks cover source facts, UUID/player aliases, exact read-only website searches, host boundaries, conflicting IDs/hrefs/resources, access states, malformed/duplicate JSON, complete pagination, unavailable source positions, snapshots, archives, anonymous metadata, cancellation, denial and redirected identity. Seven generated-media checks fully decode source, selected, inspected and converted audio, preserve exact originals and encoded packet order, and reject incomplete sources without changing prior media or recording archive success. Dynamic-service checks accept longer complete delivery and reject sources shorter than the program. Credential-bearing caller requests cannot pass those credentials to public playback.

Live native downloads used [Introducing Public Health is Dead](https://public-health-is-dead.simplecast.com/episodes/trailer), UUID `b2be5ffe-1122-4702-af9b-9bbec8f81fce`. The episode player, hosted episode page, inspected podcast selection and audio conversion fully decoded their processed and original files. A website-host parsing error caught by the core checks was corrected before the successful hosted-page workflows.

The public website listing contains 15 published episodes, despite the podcast's general metadata count of 20. The trailer retained original source position 15. The native provider also completed all 3,170 published episodes of [Busted Open](https://api.simplecast.com/podcasts/b1b3305e-9f9e-440b-a964-da710a592bfc), across 32 validated API pages. General unfiltered counts are not substituted for public listing counts.

The trailer's episode, player and selected outputs each contain a 2,546,144-byte processed MP3 and exact 2,546,066-byte original, with 6,090 decoded frames over 159.055238 seconds. All 6,090 encoded packet payloads/order and complete decoded PCM match after metadata processing. Audio conversion produced a 2,651,566-byte AAC M4A with 6,850 decoded frames over the same duration, retaining its original MP3. Eight files fully decoded; initial jobs reported two completions each and archive repeats zero.

A longer [Busted Open episode](https://api.simplecast.com/episodes/4a64cc76-fe4a-4858-b34d-d6b61e6eccef) supplied an SXM service URL. Metadata listed 1,119 seconds and 17,972,348 bytes, while an independently fetched entity contained 20,865,865 bytes and 49,794 decoded MP3 frames over 1,300.740875 seconds. An initial exact-duration check refused publication, exposing the need to distinguish this dynamic service from fixed media. Simplecast documents [dynamic ad insertion](https://blog.simplecast.com/dynamic-ad-insertion-101?hs_amp=true); inserted audio is a plausible explanation for this observed difference, rather than a proven inventory of each added segment. The provider preserves the supplied service URL and all delivered audio, without constructing an alternate source or removing ads.

The subsequent native service download delivered a different complete entity: original 19,421,401 bytes, processed 19,421,479 bytes, 46,338 decoded audio frames and 1,210.461875 seconds. Both files fully decoded; all 46,338 encoded payloads/order and the decoded PCM hash match. Two initial completions and zero archive-repeat completions were reported. Thus ten live files across both services were verified. This variation also confirms that published byte/duration estimates cannot be used as exact limits for the dynamic URL.

Scratch evidence is under `work/simplecast-probe` in the Codex workspace, including read-only public documents, generated/live results and regression logs. The scratch harness and downloaded publisher scripts are not runtime dependencies.

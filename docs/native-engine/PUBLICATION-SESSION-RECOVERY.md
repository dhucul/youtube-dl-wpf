# Processing, publication and session recovery — 0.148.0

This batch continues the independent C# replacement. Production startup remains on the original engine. Full catalog, options, account and packaging acceptance are still open.

Publication now writes a bounded, flushed and atomically replaced transaction plan before creating sibling files or moving previous outputs. The plan binds its workspace, processing recipe, complete output inventory and previous/new byte fingerprints. A restarted uncommitted installation checks the entire set before restoring previous files. Changed outputs, backups, malformed receipts, folders and links fail while retaining recovery data. A committed output set is verified and reused without media transfer. Processing debris is rebuilt from freshly validated recoverable sources.

Media, retained originals and sidecars participate in the transaction. Archive updates remain atomic and idempotent; completed output receipts survive an archive failure for later reconciliation. Metadata-only files use the same completion flow. Workspace leases are cross-process and stored outside output folders, preserving existing output-folder behavior. Legacy rollback folders without the new ownership/fingerprint information remain refused rather than guessed.

Completion claims are durable before external callbacks. A retry never repeats a claimed callback, and callback invocation occurs outside workspace/publication/archive locks so callbacks can start another download. This gives at-most-once delivery. A crash between a durable claim and callback execution can lose that callback; exactly-once external execution cannot be guaranteed. Files and archive state remain independently verifiable. A recorded archive retry skips notifications and can finish matching pending receipts.

Owned Windows media helper processes are assigned to a job that terminates them when the parent handle closes. A parent-only kill test verifies this behavior. Force-stopped processing/publication workers cover preparation, copying, backups, partial installation, full commit, archive commit and notification. Retry tests verify decoding, ordered coded packets, captions, originals, old-file protection, changed processing recipes, archive uniqueness and cleanup. Per-job lock files are retained in temporary lock storage.

Broader session checks cancel issuer operations and gate waiters when a lease is disposed, prevent late issuer responses from resurrecting cleared state, retain the previous generation after failed refresh, suppress repeated rejected-generation refreshes, and reject changed extractor, live or playlist identities. Completed SABR segments survive a retry while cookie/context/redirect/protection state from a truncated response is discarded.

# No-overwrite transfer avoidance — 0.154.0

Wistia and JW no-overwrite runs now skip media transfer when every requested media output already exists. This includes retained originals, which previously forced the download path even when they were present. JW static HLS filenames are resolved from playlist metadata before requesting a segment. The earlier report attributed the transfers mainly to final-container inference; testing identified the retained-original bypass as another direct cause.

The early check builds the complete main/original/component inventory. Declared progressive containers and predictable progressive pairs need no media request. Static HLS reads at most the selected master, video and audio playlists; initialization maps distinguish fragmented MP4 from transport streams. Separate renditions include their retained video/audio paths, and selection uses the same quality, rendition and constraint rules as the download path. Output templates are rendered independently for each extension and component.

The engine skips only when all required ordinary files exist. Edited and empty existing files remain protected by the no-overwrite policy. Existing folders, linked paths and archive/output collisions fail safely. Output-folder publication locks protect the existence check. Skips emit no new-file callbacks, require no media helper or configured download delay, preserve existing partial data, and can seed a download archive without media transfer. Recovery receipts are reconciled before the check.

Missing originals or components still use the download path to create the missing output while preserving existing files. No-post-overwrite remains a separate policy: when the caller asks for fresh originals, those originals can still be transferred and replaced. Merely existing unprocessed files do not turn that policy into a general overwrite ban.

Automatic audio output, unknown codec/container fallback, live captures, mixed HLS initialization layouts, ambiguous rendition-caption container changes and unmodeled transports remain on their existing resolution path. An incomplete HLS inventory can cause playlist metadata to be read again before transfer; this batch does not claim that all metadata requests are eliminated.

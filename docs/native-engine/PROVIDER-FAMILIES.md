# TVP, ARTE and ORF native provider batch

Version 0.206.0 adds three provider families with first subset evidence for six frozen keys: tvp:vod and tvp:​vod:series; ArteTV, ArteTVEmbed and ArteTVPlaylist; and orf:podcast. The frozen catalog remains 1,731 keys, 126 classic settings and 276 captured long names. No related embedding or family name is counted as another exact key. Complete parity and production native cutover remain open.

TVP supports modern canonical VOD/episode, explicit series and live-channel addresses, with requested product/type/page identity, external playback identity and declared clear HLS/DASH sources. Public API verification is isolated from normal media routing. Paid/login/region refusals and DRM declarations remain failures rather than becoming trailers, related clips or successful files. Series inventories read every declared season and its complete episode-array endpoint. The issuer's display range describes episode numbers, not item count: multiple distinct making-of items can share a number. Every number in the bounded declared range must be present, all actual items/positions are retained, and each item must belong to the selected season/series. Unavailable entries remain visible. Incomplete/ambiguous inventories fail without partial success. Guest media redirects permit the observed TVP CDN and publisher-issued HTTPS v4.cache.orange.pl delivery chain; unrelated/insecure redirects remain refused. Legacy TVP, separate legacy embed/stream keys, entitled accounts and broader provider-specific captions/alternate routes remain open.

ARTE supports declared recorded programme configurations, validated player embeds, programme chapters/age metadata and explicit collection editions. Language and provider identity must match the selected request; every media manifest filename is bound to that programme ID. Media remains confined to approved publisher CDN origins. A root collection that resolves to another season/edition is refused until the caller selects that explicit edition. Issued complete single-page arrays retain order and unavailable positions; paginated collections and broader parent/category inventories remain pending. Playback rights, geo/time-window errors, disallowed embedding and declared DRM are preserved. Multi-language adaptive resources continue through native manifest selection; complete upstream version/format, live and caption parity is not claimed.

ORF supports current Sound podcast series and individual episode routes. Podcast identity/station/slug/canonical links and exact episode GUID/page/duration are validated. Complete inventories must match episodeCount and retain every source position without signed playback URLs. Fresh selected playback uses full MP3 enclosures with a declared size and a filename bound to the episode GUID; unavailable/expired/protected/account-only episodes never become successful public playback. Broader ORF ON/radio/FM4/IPTV/legacy, non-MP3/video podcast and transcript/caption routes remain open.

All three families use bounded public API reads, source-cookie/header/referrer/query/authorization isolation and provider-scoped geo verification connections. Ordinary media uses its original proxy/transport and the existing native lease, signed-link graph, archive and publication controls. Owned real HTTPS proxy tests verify separate API/media routing, one bounded renewal and preserved media denials. Saved inspected selections revalidate membership before media; changed selections fail without transfer, callback or archive update. Protected no-overwrite/archive cases, process ownership, full decoding, source retention, FLAC conversion and interrupted processing/publication retain native behavior. The three new WPF checks exercise actual provider routing and metadata through the adapter.

Real TVP capture exposed an existing HLS graph/recorder mismatch: the publisher re-anchors overlapping audio PROGRAM-DATE-TIME values by about 11ms while durations, ranges, cipher and resource identity remain unchanged. The live recorder already admits a 50ms wall-clock tolerance. The adaptive graph now admits that same bounded live-only change, using independent immutable facts and retaining the original full fact strings and first recovery binding. Static manifests remain exact. Changes beyond 50ms, lost clocks, durations, ranges, encryption/initialization/format facts and unrelated resources still fail. Ten boundary/mutation/refresh/recovery checks cover this change; unchanged static/live initial HLS recovery keys are compared against the verified 0.204.0 binary. Current public TVP paired audio/video capture succeeds after this correction. The broader affected HLS suite is rerun alongside all current core and app checks; the complete optional HDR suite is not claimed as rerun.

Fourteen retained generated workflows cover TVP HLS/DASH/live/collections/renewal, ARTE programme/embed/collection/renewal, ORF MP3/conversion/collection/renewal and interrupted ORF processing/publication. Negative media cases retain actual access denial and stale ARTE/ORF inspection failures. Three actual guest playback workflows verify a bounded TVP INFO live capture, a complete ARTE programme and a complete ORF episode. Actual inventories contain 17 TVP items, 11 explicit ARTE season items and 21 ORF episodes. Independent reads compare every inventory ID and position with the first-party endpoints. Detailed final check counts, full decoding/comparison totals and candidate hash are recorded in implementation-status.json and the retained independent evidence.

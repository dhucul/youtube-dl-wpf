## Implemented

`YouTubeProvider` is registered in the C# provider registry. It recognizes watch links, short links, Shorts, live-video links, embedded videos, mobile/music hosts, and the privacy-enhanced embed host. Video identifiers, host boundaries, ports, and repeated query parameters are validated. Supported aliases resolve to the canonical watch page.

The provider reads `ytInitialPlayerResponse` as JSON without executing page scripts. Metadata includes the video identifier, title, author, description, duration, current live status, thumbnail, captions, and player-script address. Formats retain their site identifier, codecs, dimensions, frame rate, bitrate, file size, audio language, and availability. Missing playback permission and mismatched video identifiers fail explicitly.

Exposed HTTPS media URLs can be downloaded through the C# engine. The optional managed player runtime transforms encrypted signatures and throttling parameters for a recognized public player layout; a fixture download exercises the resolved address. When a watch page supplies only SABR formats, the provider now requests an IOS playback context and connects supported clear formats to native SABR transfer. Unknown player layouts, failed transformations, protected formats, and invalid playback contexts remain unavailable. A ready transport does not guarantee that the server will permit the complete video. See `PLAYER-RUNTIME.md` for the optional runtime, dependencies, bounds and evidence.

`MediaDownloadPlan` selects tracks according to the requested mode and resolution limits. Separate video/audio are paired with default-language audio and a compatible container when possible, then merged by ffmpeg. Requests for an unavailable explicit format fail before media transfer. Jobs targeting the same output stem are serialized. The ffmpeg runner terminates and drains its child process on cancellation. Converted files are staged before replacement, and metadata values are passed as separate arguments.

Public playlists now use native JSON parsing and browse continuation requests with the client version supplied by the page. Both legacy playlist renderers and current video lockup models are supported. Unavailable entries preserve their positions. Index/range selection, stop/continue after errors, partial output lists, and completion callbacks are tested. Cancellation propagates while completed files remain on disk. Repeated continuations and configured size limits fail explicitly. Watch links with playlist context can still select only their linked video using `DownloadPlaylist=false`.

Public channels now expose native Videos, Shorts and Live-tab inventories, with selected-feed pagination, channel identity checks and deduplication. Bare channel URLs combine the offered upload tabs while explicit tab URLs stay within that tab. Live Blender Studio enumeration returned 285 uploads, and a selected jawed channel video downloaded and fully decoded through native SABR. See `YOUTUBE-CHANNELS.md` for verified URL/layout scope and remaining channel workflows.

Exposed authored and automatic captions use the shared native caption pipeline. Language selection and MP4/Matroska embedding are fixture/media-tested; live caption authorization and translated tracks remain unverified. See `CAPTIONS.md`.

Chapter extraction reads the current video's player overlay and chapter engagement panels, with ordered description timestamps as a fallback. Related-video chapter records are excluded. Known duration supplies the final chapter end. MP4 and Matroska embedding use bounded, escaped FFmetadata documents, preserving literal titles and millisecond boundaries. A replay of the saved `jNQXAC9IVRw` page returned three chapter markers; this does not establish live media playback.

## Streaming protocol foundation

Local C# UMP/protobuf readers, playback request encoding, control state, segment assembly, ordered track staging, and a bounded HTTP session loop now serve the native download pipeline. Timing supports both milliseconds and precise ticks. Controlled HTTP sessions retain configured cookies/headers/proxy while validating redirects manually. Incomplete network responses can retry within the same session; completed segments are acknowledged and unfinished buffers are discarded. Explicit playback denial, stalled responses and output write failures stop the transfer. See `TRANSPORTS.md`.

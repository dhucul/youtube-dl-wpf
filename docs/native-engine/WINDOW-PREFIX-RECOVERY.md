# Dropped live windows and SABR prefix recovery — 0.144.0

This batch continues the independent C# replacement. Production startup remains on the original engine; the full catalog, option, private-account, and packaging gates remain open.

Live recordings now retain bounded, durable segment descriptors and verified completed media. A retry can restore a beginning that has left the advertised HLS window or a removed DASH period, provided the current source still exposes a matching saved overlap. That overlap is fetched fresh and must match the source, selected format, initialization, timing, and bytes. Every imported fragment must match both its owned receipt and its saved SHA-256 digest. Missing overlap, sequence/time gaps, changed media/codec/period identity, and damaged receipts fail before publication.

Clear and AES-128 HLS are covered. Recovery stores already decrypted media, so a dropped segment's old key can disappear without making that saved segment unusable. Current overlapping and new encrypted segments still require fresh keys and fresh decryption. Keys, playback URLs, cookies, passwords, proof tokens, server contexts, and pending protocol frames are not serialized in the recovery journal. Separate audio/video retain their original shared start and end. DASH restores the saved synthetic sequence/discontinuity numbering through a matching period/presentation identity.

SABR retries obtain a new session and initially advertise empty buffers. Restoring a saved prefix requires an accepted authorization status of 0 or 1, matching fresh initialization and completed media for every selected track, and fresh declared track bounds. Status 2 alone is a startup preview and cannot authorize restoration, including when an entire recording was previously cached. Status 3 remains terminal. Restored ranges are advertised in subsequent requests so their remaining media need not be sent again. Replayed segments must also match their timing, not just their payload. NoContinue transfers fresh.

The batch adds 11 core and 30 generated-media checks. Positive HLS/SABR outputs fully decode and retain ordered coded video/audio packets; removed DASH period recordings retain the full eight-second, 200-frame video; paired HLS verifies synchronized offsets and event endings. Negative checks cover disappeared resources, no overlap, gaps, corrupted cache/metadata, changed bytes/times/codecs/period identities, early/late denial, preview-only authorization, and incomplete live captions. Prior files, archives, completed-file callbacks, retained sources, and successful workspace cleanup are checked.

All **2,337 native checks** (1,671 core and 666 media), **76 app checks** and **48 focused checks** passed. Release build: zero warnings/errors. The public native app-adapter retry used a fresh anonymous YouTube session, restored the saved prefix, and avoided retransmission of **6** saved media segments. All four output/source files fully decode. Three ordered packet inventories are byte-exact; all 5,004 source AV1 coded units and presentation times match after removal of only the 12 00 temporal delimiter during remux, as documented in the previous batch. Archive repeat reads only publisher metadata, performs no media transfers/callbacks, and successful publication removes the recovery workspace. Failed preliminary transport-harness attempts are preserved separately; they are not counted as successful evidence. No saved account was accessed.

Known bounds: recovery currently requires a fresh overlapping saved segment. Renamed or revised incompatible periods are refused. Dropped-prefix live captions are explicitly refused because their old cue state is not yet durable. True abrupt live/SABR process-termination checks, broader session/proof cases, and real private-account evidence remain open; real account verification is user-deferred. Old journals without typed descriptors retain the earlier full-prefix replay requirements.

# Recorded radio, Radio France and geographic settings

Version 0.210.0 fixes the sampled recorded-radio blocker, adds current Radio France recorded episode and complete podcast/series subsets, and implements the two country/IP classic settings according to their captured forwarded-header contract. Three classic settings remain globally refused: Auth.ApMso, Auth.ApUsername and Auth.ApPassword. The frozen 1,731 extractor keys, 126 classic settings and 276 long names remain intact. No complete parity or native production cutover is claimed.

The retained ORF sample contains 6,960 complete MP3 frames followed by one extra byte, 0xFF, which is the prefix of another sync word. FFprobe reports that byte as an additional one-byte packet; strict decoding fails on it. The native ORF radio route now validates the entire declared MP3 clip structure: bounded ID3v2 header, complete Layer III frames, stable MPEG version/sample rate/mono-stereo profile, finite frame count and exact EOF or the single observed non-frame sync byte. Only that byte is normalized. An incomplete frame, other trailing bytes, changed profile or malformed structure fails before publication. Every normalized input then undergoes the existing strict full decoder and complete-duration checks; payload corruption still fails. There is no decoder-error suppression and no coded audio frame is discarded.

With KeepOriginal, the exact received progressive object is retained as the audio component, and exact ordered source objects remain the part components. Normalized output and converted output retain all complete coded audio; FLAC preserves the decoded samples. Source modification times are preserved. Existing-output inventories include the extra progressive source component, so no-overwrite checks can skip without another media transfer. Interrupted processing remains protected and repeat archives skip media. The implementation is scoped to the declared ORF MP3 clipping contract; unsupported tags, free-format/other MPEG layouts, other trailing data and undeclared providers do not acquire silent repair behavior. Joined MP3 still promises exact coded-frame order, not independent interior gapless trims. Default packed-AAC raw output naming and broader ORF formats/routes remain on the backlog.

Radio France uses the current first-party __data.json route. A bounded independent C# JSON-reference reader handles objects, arrays, primitives, undefined/hole sentinels and declared Date values. Cycles, invalid references, unknown tags, duplicate fields, oversized/deep expansions and non-data responses fail. No publisher JavaScript executes. Selected canonical page/path/station, content type, numeric page identity, publisher UUID, audio manifestation UUID, full duration and approved HTTPS media origin must agree. The native archive identity matches the frozen FranceCulture numeric page identity. The historical radiofrance radiovisions key is a different route and gains no evidence from this work.

Current recorded episodes use declared complete M4A/MP3 audio objects and issuer-owned bounded renewal. Unavailable, account/region/DRM, changed publisher UUID or changed used manifestation failures remain failures. Existing publisher cover artwork is retained in unchanged objects; it is an attached image rather than an additional moving-video role. Collections use their declared Concept type (podcast/Podcast or serie/Serie), total, page size, last page and exact previous/next offset cursors. Every page is read, complete counts/order and publisher membership identities are checked, duplicates/partial/changing pages fail, unavailable positions remain visible, and signed playback URLs are absent from inventories. Selected and inspected members bind their publisher UUID and obtain fresh playback. Explicit series membership is separate from the episode's original programme relationship. Current live stations, personal profiles, schedules, legacy radiovisions and broader routes remain open.

The two geographic settings are forwarded-header controls in the frozen upstream contract. Native handling now selects one IPv4 address from the requested CIDR or one of 240 frozen country/range compatibility entries and keeps it stable for a prepared job and its resource renewal/child sessions. The table is a historical compatibility hint, not an IP geolocation database. Inputs are validated before HTTP. Standard IPv4 CIDR and supported two-letter codes, --xff, both classic aliases and enable/disable aliases retain last-option precedence; WPF applies its existing country-then-IP ordering after the enable flag. Default/never do not invent a forced address. Default provider-country inference remains a separate broader contract. Explicit ordinary source headers keep their existing precedence; dedicated verification sessions carry only the dedicated forwarded policy, while unrelated public-service/OAuth/SponsorBlock sessions clear it along with source credentials. The ordinary proxy, socket source address and real server access decisions are unchanged. The header is omitted from exported request metadata and redacted option strings. Actual owned HTTP and curl workflows verify delivery, job stability and retained denial behavior.

Adobe's current client-to-server flow still requires registered application context, MVPD authentication, resource-bound authorization and session lifecycle handling. Its three saved fields are not accepted as no-ops. Real-account verification remains explicitly user-deferred; no saved account, browser profile or netrc is inspected. Continue missing families alongside that integration work, including ZingMp3, Polskie Radio/Onnetwork, Niconico, Mellowfan and remaining broadcast/hosting routes. Polskie episode grants must match the selected external ID; the known unrelated Onnetwork default filler is not playback evidence.

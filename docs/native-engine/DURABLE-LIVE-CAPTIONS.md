# Durable live captions and interrupted recording recovery — 0.146.0

The C# replacement now retains live caption state alongside recoverable media. This is a verified subset; production startup remains on the original engine and full provider, option, account, and packaging acceptance remain open.

Each selected HLS WebVTT or clear DASH wvtt/stpp track has a bounded, flushed, atomically replaced snapshot. It retains decrypted caption data, initialization, timeline mappings and period boundaries. Source addresses and recording/format selections are bound through hashes. Snapshot entries validate their data and descriptor digests; malformed, changed, excessive, duplicate or linked snapshots fail. No playback addresses, encryption keys, account credentials, proofs, cookies, or server contexts are written into the snapshot.

A retry obtains current media authorization and verifies the saved media overlap first. It then fetches the current caption rendition and validates available overlapping caption initialization, timing and payloads. A caption window directly contiguous with the saved end can continue after fresh access and schema checks; gaps and changed sources fail. Saved old cues are replayed when dropped media is restored, retaining the original shared output start. Caption budgets include restored input. WebVTT header/range/AES state and DASH period/sample offsets remain consistent through saving, conversion and embedding.

Compatible narrowing of a captured DASH trailing segment now updates its durable media descriptor atomically, including a related initialization receipt where present. Imported and current initialization objects are canonicalized so a restored period preserves one initialization reference. These changes prevent a restart from treating a declared period closure as a gap or a container change.

The tests launch actual recording processes, wait for flushed checkpoints, verify the worker PID, force-stop those owned processes without cancellation/disposal, and retry in a new process context. HLS clear/AES/range/reset/SRT, paired media, DASH WebVTT/TTML/range/audio/video and negative caption cases are covered. SABR checks cover partial track progress, replay, changed cache, denial and startup previews. One worker is stopped with an unfinished audio UMP frame after completed video segments; only completed records are restored. Fresh session requests do not contain the dead process's cookie or control contexts. Previously empty selected tracks transfer fresh while their matching authorized sibling prefix can resume.

All **2,372 native checks** (1,682 core and 690 media), **76 app checks** and **42 focused checks** passed. This batch adds 11 core and 24 media checks. Release build: zero warnings/errors. Two actual public DASH-IF native app-adapter recording workers were force-stopped after durable media/caption checkpoints. Retries preserved prior files, retained sources, saved/embedded captions, archived correctly before HTTP, and cleaned the owned recovery workspaces. All eight files fully decode. WebVTT main/original: 74.010 seconds, 2,220 video and 3,469 audio frames; retained video 74.000 seconds and audio 74.010 seconds. TTML main/original: 12.170 seconds, 363 video and 563 audio frames; retained complete video source 14.000 seconds/420 frames and audio 12.010 seconds/563 frames. Duration controls retain complete segment boundaries and paired trimming; these are measured capture spans. All four saved prefix cue payloads per job remain in the final sidecars. All 74 WebVTT and 13 TTML final cues are embedded and inside the decoded output windows. Four nonempty ordered main/original video/audio packet inventories are byte-exact. Whole retained components can extend beyond the paired output trim; no byte-equality claim is made for those extra intervals. Public probe engine bytes match the final compiled engine. Real private-account verification remains deferred.

Remaining: recovery without any fresh media overlap; incompatible changed/renamed period semantics; more crash positions inside checkpoint writes, processing, publication and archive updates; wider publisher/session/player/proof and remote private/signing cases. Real account verification remains user-deferred. Media or captions never captured before the stop cannot be reconstructed when the publisher has removed them; such retries fail without changing previous media, sidecars, archives or completed-file callbacks.

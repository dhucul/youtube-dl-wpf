# Native external downloader batch

Version 0.202.0 adds an explicitly selected curl transport for HTTP/HTTPS progressive files, separately selected progressive audio/video and HTTP-sequence parts. The default remains the native HTTP transport. A curl selection performs real remote network transfers in curl; it is neither an ignored setting nor a loopback relay. Other external programs, protocol-specific selector maps, arbitrary curl options and adaptive HLS/DASH/SABR/live delegation remain unsupported. Six global classic settings remain refused: three geo and three AdobePass controls. Full replacement and native production cutover remain incomplete.

The saved Network.ExternalDownloader and Network.ExternalDownloaderArgs settings map into immutable native requests. Typed --downloader/--external-downloader and --downloader-args/--external-downloader-args aliases append argument groups after saved arguments. Supported downloader choices are blank/native, curl/curl.exe, or an explicit absolute curl executable path. The named curl choice resolves the system installation rather than searching the working directory. Arguments require curl. Analysis projects these download-only choices out; metadata-only, archive and supported no-overwrite paths perform no delegated media transfer. Default JSON, publication recipes and track recovery identities match the verified 0.200.0 binary. Backend/argument changes are operational and do not invalidate source recovery.

Argument groups accept optional curl: targeting, option/value pairs or --option=value for --connect-timeout, --max-time, --speed-time, --speed-limit and --limit-rate. The no-value switches --http1.1, --no-buffer, --tcp-nodelay and --no-keepalive are accepted. Numeric counts are positive/bounded, speed counts are integers, and rate suffixes K/M/G use native parsing. Output/config/header/URL/redirect/retry flags, additional URLs, shell commands and arbitrary behavior overrides are refused. In WPF extra arguments, quote a complete argument group with double quotes, for example --downloader curl --downloader-args "curl:--max-time 120 --tcp-nodelay". Native C# argument-group parsing also accepts single quotes inside a group.

Native discovery and issuer requests continue through the existing HTTP session. Only selected file GETs use curl. Scoped playback headers, cookies, proxy, source address, IP family, certificate policy and native 401/403 signed-link renewal feed each transfer. Curl receives URL/header/proxy values through escaped private stdin configuration, never dynamic command arguments or temporary configuration files. Its default curlrc is disabled before all other options, automatic netrc/auth is not enabled, and implicit TLS key-log/override environment variables are removed. Output/errors are drained with bounded memory; URLs, cookies and process stderr are not echoed in transfer errors. Explicit source content headers requiring a GET body and opaque injected handlers are refused rather than silently changing transport/session semantics.

Public file redirects are bounded, reject HTTPS downgrade and embedded-credential URLs, update the native cookie jar and strip authorization after redirects. Cross-authority redirects retain only a small safe header set; cookies are selected again from the jar for each target. Provider-authorized playback disables handler redirects so the existing native scoped redirect and renewal policy remains in control. Identity encoding, bounded informational/header blocks, unambiguous lengths, complete body consumption and successful curl exit are required. Curl owns network transfer; native code owns streamed durable writes, SHA/size/decoder verification where declared, rate/progress, retry scheduling, strong-validator resumes, bounded HTTP chunks, direct-write rollback, processing and publication. Cancellation kills/reaps the owned process tree; the existing Windows kill-on-parent-exit job guard covers abrupt parent death.

The focused downloader run passes 65 checks (seven foundation, 52 new core and six media). This batch reruns the complete core suite and affected media workflows; it does not claim a rerun of the full optional HDR/live suite. The prior 0.200.0 checkpoint retains its 4,199 full-suite result. New core cases cover byte preservation, cookies/custom headers, chunked/interim responses, redirects/credential scope, signed renewal, interrupted/changed/invalid-range/416/chunk transfers, direct writes, sizes, cancellation/deadlines, encoding/header limits, actual HTTP proxy routing, backend/argument refusals, protected jobs, aliases/analysis and default/recovery compatibility.

Six retained generated media workflows cover progressive downloads, private-token renewal with owned fixture credentials, separate-track merging, FLAC conversion, ordered HTTP sequences and interrupted processing/publication followed by native-backend recovery.

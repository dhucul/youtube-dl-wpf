# ORF ON and radio native batch

Version 0.208.0 adds two independent C# provider subsets, orf:on and orf:radio, alongside the existing ORF podcasts. The original 1,731-key catalog, 126 classic settings and 276 long options remain unchanged. No complete parity or production native cutover is claimed.

ORF ON accepts current numeric video and profile routes, with optional title slugs. Each job reads the publisher's bounded public homepage client configuration, pins its API base origin, and confines its issued public Basic client credential to that API. Source cookies, account headers, referrer and query credentials are excluded; no saved account is inspected. This is the site's public client configuration, not a user login implementation. API redirects, changed API base, resource identity/type, duplicate formats and foreign source resources fail. Fresh episode HLS/DASH sources bind to the selected numeric episode in their filename; actual issuer delivery permits only apasfiis.sf.apa.at and the observed vod-ww.mdn.ors.at chain. Unrelated ORS delivery hosts remain refused. Complete gapless recorded sources are required. DRM, active youth protection, declared geo/account/time denials remain failures. Native selection uses declared quality identifiers and adaptive manifest selection without inventing pixel dimensions. Declared German VTT/SRT/TTML tracks retain stable subtitle identity, automatic-caption status, native saving/conversion/embedding and renewal. Broader language/account, non-gapless segments, player variants, television live and alternate edition/profile formats remain pending.

ORF ON series read the selected profile and every episode page, validating page/limit/total/pages and stable selected parent membership. Missing, duplicate, repeated or changed bounds fail. Inventories retain unavailable entries and source positions without playback resources. Inspected selections obtain fresh playback and revalidate membership before transfer. The public WeltWeit profile currently exposes 73 entries; fixtures additionally exercise 101 entries across two pages.

ORF radio accepts current Sound programme/item, available calendar and public live station routes, plus canonical first-party broadcast/item API addresses. The station allowlist covers the twelve declared national/regional ORF stations. Complete available calendars retain all days and positions, including pending or unavailable entries; this is the API's published horizon, not an unlimited archive. Programme selection matches the exact programKey in the available calendar before fetching its selected broadcast ID. Broadcast/item identities, station, entity, API links and complete stream time coverage are checked. Editorial item duration may be rounded; the supplied stream interval is authoritative. MP3 resource hosts, channel, recording ID, offsets and supported literal URI-template expansions must agree. The public player's shoutcast=0 parameter is expanded explicitly. A gap, overlap, missing start/end, unsupported field or changed identity fails. Multiple complete parts use ordered HTTP sequence transfer; they do not acquire invented signed-token semantics. Single progressive and ON adaptive/caption sources use existing bounded native renewal. Live radio uses the exact station HLS template issued by current ORF Sound configuration.

The shared ordered downloader now supports audio-only MP3 alongside existing MP4/FLV, with complete per-part decoding, stream/codec/layout/time-base compatibility and joined decoding. Whole encoded MP3 frame counts determine concatenation clocks because presentation duration can exclude encoder delay/padding and otherwise overlaps DTS. Difference from the declared interval is bounded to two encoded frames; no FFmpeg error is ignored and no coded packet is discarded. Exact ordered coded-packet preservation is verified for distinct source tones; per-file originals remain byte exact. MP3 does not express independent interior gapless trims in one joined stream, so this subset promises complete coded-frame retention rather than decoded-sample equality across interior encoder padding. Changed layout, corrupt parts and excessive clock differences fail without publication/archive/callbacks. Protected no-overwrite inventory and interrupted publication/recovery are covered.

Current ORF live HLS exposes packed ADTS AAC without an initialization map. Live verification now identifies that exact local single-track AAC container, still requiring a complete nonempty decoded timeline. An unprocessed live output is itself its retained original. It currently retains the existing raw HLS .ts filename extension; automatic packed-AAC output naming remains pending. Verification identifies actual AAC content independently of the filename. Other nonfragmented containers remain refused; MPEG-TS and fragmented MP4 contracts remain in force. This does not add static/multiperiod packed-audio joining or claim broad discontinuity/codec transition support. A live recording with no selected HLS caption also avoids the unnecessary subtitle-clock lookup; selected captions still require their actual synchronization clocks.

# Native exec and SponsorBlock batch

Version 0.200.0 adds supported subsets for two previously globally refused classic settings. Eight global refusals remain; full replacement, complete option parity, account evidence and native production cutover remain open. The frozen catalog remains 1,731 keys, 126 classic settings and 276 long option names.

Exec runs at after_move for a newly installed primary media file, before publication commit, archive update and file callbacks. It invokes a fixed program with separate arguments, without a shell. `--exec` entries run in order after saved settings; `--no-exec` clears earlier entries. Complete-argument `{}`, `%(filepath)q`, `%(_filename)q`, `%(title)q`, `%(id)q`, `%(uploader)q`, `%(extractor)q`, `%(webpage_url)q` and supported duration/playlist_index numeric conversions bind literal data after tokenization. With no fields, the final filepath is appended. Fields cannot select the executable or be interpolated inside command/code strings. Inline shells, pipelines, redirection, other stages and broader templates remain unsupported. Known interpreter code arguments cannot be metadata fields.

Execution intent is durably saved before process launch. Output streams are drained with fixed memory, cancellation kills/reaps the owned process tree, and the existing Windows process-lifetime guard applies. The journal stores recipe/invocation/output fingerprints and execution progress rather than command text or credentials. Process failure/cancellation restores prior files when the installed candidate is unchanged. A command must preserve the media/sidecar set: modified files are not adopted automatically, and protected prior backups remain available when safe rollback cannot identify the candidate. The pending exec journal is raw/.native-exec.json inside the owned .native-download-* workspace; publication.json records target/backup identities. An interrupted or failed command whose intent was recorded is never automatically replayed; retry fails before new media transfer and requires explicit operator review or a deliberately new job. Completed read-only commands can recover without replay when the same invocation/output fingerprints are reproduced. Skipped, simulated, metadata-only and archived media do not run commands. Arbitrary external side effects cannot be made transactional; modifying-media command workflows remain pending.

SponsorBlock uses the official anonymous HTTPS hash-prefix read API for recorded YouTube IDs, with no source cookies, custom headers, referrer, signed resource queries or playback authorization in that service session. Redirects, malformed responses, mismatched identity/duration/category/action and ambiguous segment IDs fail; 404 or a valid prefix inventory without the selected video means no segments. Prefix collisions are bounded independently from the selected video's 500-segment plan. The accepted plan is flushed to the owned raw workspace and pinned across processing retries, so changed/unavailable service data cannot silently alter the same pending edit.

Marking supports the standard named categories, all/default, ordered inclusion/exclusion and point/chapter actions, composing labels with source chapters. Removal takes precedence over marking and uses only skip actions; default removal excludes filler, and point/chapter categories cannot be removed. `--no-sponsorblock` clears both controls. Native removal currently accepts one aligned recorded clear MP4/M4A program, with at most one SDR yuv420p H.264 video track and one AAC/ALAC/FLAC audio track. Extra embedded tracks, HDR, unsupported decoder/layout/clock inputs and a plan removing the entire recording fail explicitly. The actual complete source duration is bound before deciding whether requested cuts intersect, and checked against catalog duration. A confirmed rounded-tail defect (2.5s catalog, 3.0s complete source, requested 2.6-2.8s removal) is fixed and verified as 2.8s output; the initial full run was stopped and restarted for this correction. AAC priming preservation now follows whether the timeline was actually edited.

Removal uses the union of intervals once. Each kept video picture retains its source position projected through the common edit map, including VFR timing and cuts between frame boundaries. Video is encoded as lossless H.264; audio is trimmed on sample boundaries and encoded as ALAC. This intentionally changes processed codec/size; retained original media stays packet-identical. Caption cues and source/SponsorBlock chapters use the same map, splitting crossing cues, removing cut payloads and clipping to the resulting duration. Saved VTT/SRT and explicitly converted/embedded TTML are supported; unsupported caption formats fail, and wholly removed caption tracks are omitted. Other containers/codecs/HDR, separate embedded tracks, offset clocks, live inputs, custom API/title grammar and full upstream semantics remain pending.

WPF settings, general/job extra arguments, case handling, immutable job capture and read-only analysis are verified. Tool availability for explicit fixup/SponsorBlock processing is now checked before media transfer. No-overwrite checks precede SponsorBlock API reads, and archive repeats precede all new command/API/media/callback work.

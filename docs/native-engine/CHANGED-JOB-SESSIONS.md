# Changed jobs, recovery locations and issuer sessions — 0.152.0

This batch continues the independent C# engine. Full replacement acceptance remains open; production startup still uses the original engine.

A committed output set is no longer rolled back merely because the caller changes processing options. New publication plans record whether completion requires an archive and, when needed, the exact archive path and validated media identity. Changed jobs first validate the committed output set, reconcile the original archive, retire prior delivery intents and finish checked cleanup. They then run the new job against those committed files as its preimages. A later processing failure leaves the prior committed media and originals intact. An archive-backed source already recorded in the chosen archive keeps its normal deduplication behavior.

Archive and workspace locks are acquired in their ordinary order. Recovery writes track archive temporaries without recursively acquiring the held workspace lock. Locked archives or backups, edited media or recovery records, canceled waits and interrupted retirement retain the pending data. Tests force-stop actual workers during original publication and again during retirement or cleanup. Metadata-only outputs use the same completion-context flow.

Recovery locators are also registered in bounded local temporary storage, keyed by the hashed source address and workspace scope. The registered record binds the original locator path, recipe and owned workspace. This allows recovery after changing the configured output folder, and permits matching registered absolute destinations to be found without scanning a drive. Matching locators are checked for agreement; records for vanished owned workspaces can be retired. Old local locators are removed when registration moves, and completion removes both records. Partial or abandoned writes are bounded and cleaned on retry.

Legacy receipts remain readable. A legacy committed receipt whose archive requirement is unknown cannot safely be retired under different settings until its original completion is acknowledged; it is retained with its media. Existing literal-prefix discovery remains available for unregistered receipts. This does not locate arbitrary pre-registration absolute outputs whose paths are no longer known.

Google and Vimeo OAuth sessions now cancel and drain initial identity reads, refresh grants, account validation, resource reads and queued callers when disposed. Late responses cannot restore credentials. Replacement tokens are installed only after account identity validation; failed or switched-account grants preserve the valid session. API replays compare a monotonic session generation, so simultaneous rejections share a refresh even when the issuer returns the same access-token string. A canceled waiter leaves surviving callers usable. Disposed HTTP owners cannot create redirected, anonymous, cookie, query, header or playback-authorized child sessions.

Kaltura's default playback referrer removes ks and encoded flashvars[ks] query fields while preserving publisher and player parameters. The same public referrer is used for API playback-context requests, media and adaptive renewal. Explicit publisher referrers remain supported. Supplied session keys remain in their selected API request bodies. Generated checks verify first playback and renewed media without placing the session key in media headers.

## Supported behavior

Selected live HLS WebVTT fragments are captured alongside media before a moving window can discard them. The supported live path requires consistent program-time mappings on media and caption playlists, and uses WebVTT timestamp maps and the actual source media clocks to place cues. It handles separate audio/video, clock resets with matching discontinuity identities, initialization headers, AES-128 and exact byte ranges. Duplicate continuing cues are joined, each period clips its own cues, and the final common audio/video end clips the complete document. Bounded recordings of complete HLS retain the existing static caption path.

Clear live DASH captures selected fragmented WebVTT (`wvtt`) and supported TTML (`stpp`) alongside the selected media. Inherited SegmentTemplate/SegmentList addressing, presentation offsets, full-MPD refresh, available fragments, period resets and expired-period removal share the media session. Each caption period retains its initialization and sample origin; conversion produces a recording-relative VTT document. Existing language selection, subtitle conversion, saving and embedding consume that resolved document. Unselected captions issue no resource requests.

Caption acquisition shares the media rate budget and enforces eight MiB per track and 32 MiB across selected tracks, segment/cue/output bounds, cancellation and a bounded lag wait. Missing intervals, changed descriptors, unavailable selected tracks, corrupt fragments and unsupported layouts fail before final media/sidecar/archive publication. Encryption keys are refreshed across HLS snapshots and cleared on disposal. Known job-owned playback tokens are canonicalized before caption identity comparisons and metadata retention.

DASH media segments that overlap a period boundary are now retained as complete source resources and mapped onto their visible intervals. Closing-period timing is durable across shared refreshes, so slower audio/video workers can apply a closing trim even after that period disappears. The shared window trims substantial initial preroll and avoids selecting a previous segment that only touches the start because of clock rounding.

Decoded clipping now also supports compatible clear HEVC/VP9/AV1 8/10-bit planar MP4 video and Opus/FLAC audio; H.264/AAC/ALAC support remains. See LIVE-PERIOD-SESSIONS.md for output codecs, limits and verification. It uses local ffmpeg trimming through lossless intermediate video/audio. Clipped H.264 output is lossless; AAC is encoded once at 256 kb/s after clipping, while ALAC stays lossless. Complete source periods are retained when KeepVideo/KeepOriginal is requested. Other codecs/containers and unsupported pixel/sample precision requiring clipping remain explicitly unsupported. Unclipped transport keeps its existing stream-copy path.

Small audio delays exposed an AAC priming case that needs an additional MP4 edit. The native correction safely grows a bounded trailing movie header when required, retains the coded priming packet, and preserves the declared delay after subtitle/metadata remuxing. Existing two-entry edits retain their supported correction. No coded media offsets change when the trailing header grows.

References: [HLS timing and WebVTT](https://www.rfc-editor.org/rfc/rfc8216.html), [DASH-IF timing and period boundaries](https://dashif.org/Guidelines-TimingModel/).
